# Governance

The project uses a maintainer-led, review-driven model during alpha.

- Maintainers merge routine changes after review and passing release gates.
- Protocol, cryptography, privacy defaults, compatibility, and governance changes require an ADR
  and approval from two maintainers when two are available.
- Security fixes may be developed privately and merged on coordinated disclosure.
- Maintainers disclose relevant conflicts and recuse themselves when necessary.
- A contributor with sustained, constructive work may be nominated as a maintainer in a public
  governance issue.

Governance will be revisited before beta so no single unavailable person can block releases or
security response.
